# thinkerNeca — project guide

This repository is **Necaladun's fork of Thinker Mod for Sid Meier's Alpha Centauri: Alien Crossfire (SMAC/X)**. It builds on [Induktio's Thinker](https://github.com/induktio/thinker); it is not an upstream release. The fork currently targets **fresh single-player games**, with independent minor terrain, world-generation changes and experimental rules. See [Readme.md](Readme.md) for an introduction.

## Rules of the repository

- **Source code and installed data are the implementation authority.** Documentation describes observed/current behavior; if a claim conflicts with source, flag and correct it. Git history/PRs own chronology.
- **Keep `project/STATUS.md` short.** It is an overview, not a second backlog or changelog.
- **Keep actionable items in `project/WORK-QUEUE.md` only.** Use stable IDs such as `TERR-001`, `BUG-001`. Reference those IDs from other docs instead of duplicating task descriptions. State a concrete acceptance criterion for each task.
- **Keep design possibilities in `project/IDEAS.md`** until they are deliberately promoted to a task or a decision. A test setting is not a confirmed final rule.
- **Record material decisions** in `project/DECISIONS.md` with scope and conditions for reconsideration. Do not treat speculation as confirmed mechanics.
- **Use `Fork-Changelog.md` for meaningful fork changes**, not every commit or migration step. Leave the inherited upstream `Changelog.md` intact.
- **Record verification separately from implementation** in `project/TESTING.md`: source inspection, CI, user-reported in-game evidence and release validation are not interchangeable.
- **Update status, queue, tests and changelog in the same change** when a feature materially progresses. Mark completed/retired entries rather than leaving phantom WIP.
- **Avoid administrative sprawl:** no package registries, autogenerated milestone ledgers or nested process layers. Add a new technical document only when an existing document is becoming unwieldy.

## Compatibility and terminology

- **Thinker Mod is not Thinker difficulty.** Separate vanilla mechanics, mod changes, difficulty modifiers and AI behavior.
- No compatibility obligation for **old saves or custom scenarios** as the fork evolves. A *new* game must still save, reload and continue correctly on the same build.
- The distributed [`docs/thinker.ini`](docs/thinker.ini) is presently a **user-selected test profile** rather than a neutral upstream default. `thinker_user.ini` overrides settings locally if present.
- In-game acceptance is required for native x86 hooks, rendering and resource behavior. Green compilation/static CI is necessary but not sufficient.
- Keep maintainer planning under `project/`: `docs/` is copied into the game distribution by packaging scripts.
