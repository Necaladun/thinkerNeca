This is the **fork's change history**, separate from Induktio's upstream [Thinker release changelog](Changelog.md). Record meaningful work when it lands or is substantively tested; Git commits and PRs remain the exact history. **Unreleased** means present on a draft/unmerged branch, not a shipped release.

## Merged PR #4 — minor terrain and native rendering (7 November 2026)

- **7 November closeout review:** user reconfirmed prior 3/4/4 N/M/E, repeated save/quit/reload/advance and multi-seed mineral-overlap/geological patch-size tests. Qualitative Windows Develop Forest/fungus extraction, resource underlay, Unity pod reroll and ordinary save/Inspector/graphics behaviour are positively reported. Canyon source removal/slot reservation is CI-verified (its old `canyon=0` default already suppressed placement). Longer AI simulations, quantitative patch counts/economy, constructed minor stacks, variant-1 sprite and Release/PRACX native feature parity remain deferred, not accepted; PR #4 remains unmerged.


- **AI-002 Titanium auto-Mine trial (source implemented, Windows AI test pending):** automatic Formers can now evaluate nonrocky Rolling/Flat independent Titanium Mine+Road yields, protecting Flat food and nutrient improvements, weighing Forest/Fungus/Borehole, Flat Farm yield and eligible Solar, and giving viable Titanium +4 target priority. Mine/Solar pre-tech eligibility reads configured resource caps instead of hardcoded 2; distributed test `tile_output_limit=3,4,4` (N/M/E) replaces earlier 3/3/3. No general Former AI rewrite or player Mine/Road change.


- **BAL-003 targeted pod resource reward:** when a Unity pod awards an ordinary mineral resource on independent Titanium, reroll the award to nutrient or energy (equal chance) by forcing the existing explicit resource-bias flag path. The underlying Titanium remains; all other pod outcomes and Uranium+energy are unchanged. No global resource suppression or save-format change; Windows gameplay validation pending.

- **BAL-003 experimental geological extraction restriction:** independent Titanium's +1 mineral and Uranium's +1 energy no longer improve Forests in live or projected worker-yield calculations. Titanium new-map generation avoids ordinary mineral resources (both flagged and procedural) without excluding nutrient/energy overlaps; existing saves are unaffected. The existing single Mine enhancement remains while testing smaller 3–5-tile deposits. Windows runtime validation pending.

- **TERR-002 experimental geology dispersion (multi-seed qualitative Windows tests positive; statistical survey pending):** Uranium and Titanium patches shrink to 3–5 tiles (weights 1:3:1; mean 4 rather than 6), with 50% more target patches (3–9 per type instead of 2–6), preserving roughly the previous expected total geological coverage when placement succeeds. Leave naturally occurring fungus in place; players can clear it to activate the otherwise fungus-suppressed geological yield. Retain the two-tile buffer, existing bias/eligibility, no minor-feature stacking, and bounded failed-patch skipping. This is a balance trial, not yet an accepted distribution.

- **REND-001 native Jungle hook fail-closed CI test:** factor three-site verify-then-apply logic into a shared C++11 helper used by the actual x86 installer and a host-only harness. One valid and all 18 single-byte-corruption cases pass; every negative case yields zero writes and no modified simulated instruction buffers. This tests the control flow without altering `terranx.exe`. Windows Develop+Release compile CI passed (run 42328264052).

- **REND-005 experimental geology underlay (core visual path Windows-verified; edge cases pending):** live user-provided executable bytes locate original Uranium landmark mask `0x464D9C` and its sprite call `0x464DE3`, earlier than ordinary resource drawing. Develop test switch `minor_geology_underlay=1` enables strict guarded hooks that render independent geology at this earlier stage, permit ordinary resource glyphs to draw later, and substitute Titanium blue-grey artwork where present. A disabled/mismatched hook uses old renderer; no native LM or save mutation. The user now confirms on Windows Develop `34f736e` that blue-grey Titanium is visible beneath an ordinary resource icon (with the earlier Uranium+resource underlay also confirmed). The `0x78A700`/`0x78A72C` native Sprite* guard mismatch was fixed; fog/zoom/foreground, missing-art fallback, constructed feature stacks and final-binary same-build persistence remain pending.

- **Fix resource-icon priority (BUG-003; original resource precedence Windows-verified; current double-layer REND-005 separately user-verified):** normal procedural bonuses generated from map seed and coordinates must receive the same rendering priority as explicitly flagged/editor bonuses. Prior `BIT_BONUS_RES`-only check could conceal a generated resource under Titanium/Uranium art despite correct Inspector and stacked yields. `mod_bonus_at` now evaluates the complete normal resource algorithm before returning the renderer-only geological sentinel, without changing stored tile flags or yield logic.

- **Safe config bit shifts / Release cross-build:** both the `skip_facility` parser and the production-choice consumer now use 64-bit masks for IDs 33–64; `skip_event`/`skip_faction` parser masks are unsigned 32-bit. Parser/consumer contracts and separate Release cross-compilation passed CI on `4809cb7`; neither proves high-ID gameplay or native Release graphics parity.
- **Native variant diagnostics (source-level):** log four native resource-draw samples per sprite variant (0, 1, unknown), so variant-1 geometry can be captured even if it first appears late; variant-1 artwork is still unsupported pending actual Windows measurements.
- **Native hook safety / redraw cleanup (source-reviewed, Windows regression pending):** the Jungle installer preflights all three executable instruction sites before modifying any, avoiding half-installed optional native hooks. Develop skips redundant full-map overlay scans when every native minor type is enabled. The native Inspector now logs bounded successful label appends for comparison with hover diagnostics (`b76feed`).

- **Native-stage external Titanium sprite working in Windows Develop (user-verified):** mode 3 selects blue-grey Titanium from user-local 1024×1024 indexed `neca_sprites.pcx` with correct transparency, alignment and zoom-in/out; separate +1 mineral yield still works. The external Uranium mode-1 control visually matches the original native sprite. This applies only to native resource sprite variant 0; variant 1, fog/units, save/reload and Release remain separate work.
- **Correct palette processing and reproducible artwork:** PCX loader applies native +10 offset, mask conversions decoded 6/7→9 and transparent key 9. Exact Uranium control hash `24A1B67A` remains gated; editable Titanium art is validated structurally but not checksum-locked. Added a local-user-input `tools/build_neca_sprites.py`, synthetic atlas tests and [sprite atlas documentation](project/technical/sprite-atlas.md); original-game/user artwork is never committed to GitHub or CI binaries.
- **Prototype cleanup and configuration reconciliation:** retired noisy native/Inspector startup hex scans, retaining the exact verified rendering hook and actionable diagnostics. The distributed **test** `docs/thinker.ini` selects user-verified mode 3 while compiled Config default stays native mode 0 and missing artwork falls back to Uranium. Old `minor_terrain.pcx` mode 2/post-map overlay remains for now because it has live dependencies; MAINT-001 owns later retirement. Earlier failed key/colour hypotheses remain in Git history, not active documentation.

- **Latest refactor:** renamed geological mineral minor type to **Titanium** throughout the active source, INI, tests, diagnostics and docs. The saved type ID remains 3 and the `THMIN001` v2 record format is unchanged.
- Replaced duplicate Uranium/Titanium deposit generators with a single interleaved routine: same eligible tiles, lowland preference, 3–9 patch sizes, fungus clearing, two-tile inter-patch buffer, and independent RNG streams. Uranium patches are attempted first each round, then Titanium.
- Retired the older hand-positioned Titanium thunk. Both geological minerals use the native `bonus_at()==4` draw stage, with separate +1E/+1M yields; the verified narrow Sprite-pointer hook now provides distinct Titanium art in supported Develop mode.
